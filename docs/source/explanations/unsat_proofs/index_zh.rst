UNSAT 解释究竟证明了什么
========================

输入是精确的条件合取。UNSAT 表示没有任何赋值能够满足这个合取。
解释记录 Z3 如何推导出矛盾，并将证据关联到命名输入和调用者提供的来源。
性质判定、源语言语义和有界时域仍由构造这些条件的应用负责。

从原始条件到可读推导
--------------------

.. list-table:: 证据流转
   :header-rows: 1
   :widths: 25 40 35

   * - 步骤
     - 操作
     - 保留的证据
   * - 捕获
     - 将全部原始条件翻译到独立且启用证明的 Z3 上下文，并求解。
     - 输入出现位置、带类型的项、原生证明节点和一个执行 ID。
   * - 分析
     - 检查输入绑定和假设关闭，解释原生规则及精确算术证书。
     - 分别记录输入、作用域和规则检查；不支持的证据显式保留缺口。
   * - 阅读
     - 合并机械改写，保留实际算术前提和可展开的证据。
     - 有序结论、依赖、当前假设和来源关系。
   * - 可选最小化
     - 提取并复查核，只在删除尝试返回 UNSAT 后移除条件组，再对保留子集重新求证。
     - 完整原始图、新子集图，以及带保证范围的核证据。

共享节点在证据图中仍保持共享。人类文本是该图的视图，不是另一次证明搜索的输入。
默认实现使用 Z3 和确定性的 Python 组装，不需要 LLM 编写推理链。

教程中的整数余额算术可以读成：

.. code-block:: text

    -balance@0 <= 0
    balance@1 + 1 <= 0
    balance@0 - balance@1 + 1 <= 0
    --------------------------------
    2 <= 0

第二行使用了整数性，第三行来自更新等式。每个显示的加权和都保留原生参数和归一化后的
精确系数。有理数系数使用 ``Fraction``，不使用浮点数。
负的原生不等式系数遵循 Z3 的定向后取绝对值约定；等式系数保留符号。

维护证明框架
------------

原生证明翻译与局部重构各有职责。捕获层保留 Z3 的证明图；当 theory lemma
的原生提示没有展开全部算术步骤时，重构层补充精确、可读的证据。
重构不能替换原生结论，也不能解除该节点的假设。

内部实现提供三个扩展位置：

* ``reconstruction.py`` 选择既有原生快速路径和有序的局部策略。
  不可变的 ``Reconstruction`` 返回推导类别、检查状态、证据字段和诊断。
  公共分析器统一管理假设作用域、扩展优先级和超时。
* ``evidence.py`` 显式列出证据类别。不可变的 ``CertificateHandler`` 将
  canonical 节点字段、载荷类型、精确检查器和阅读函数关联起来。
  在线重构与离线加载共用回放分发；加载时不重新搜索证明。
* ``evidence_text.py`` 使用统一的公式、语言、详细度和引用上下文渲染各类证据。
  ``text.py`` 保留来源链接、假设、领域折叠和最终结论。校验顺序与展示顺序
  分开记录，保持已有多证据快照的行为。

支持已有证据类别中的新规则时，按需扩展对应的生成器、精确检查器和阅读函数，
先增加失败用例及损坏证据的反例测试。真正新增证据类别，还需要 typed canonical
记录、``io.py`` 中严格的解码及引用校验，以及目录项。加入目录并不会自动使新载荷
可以安全反序列化。必须保留 canonical 往返测试，并用 ``text_aligner`` 比对完整阅读文本。

目录是内部固定实现，不提供可变的全局插件注册。包括 BMC 在内的应用继续通过
``ProofExtensions`` 扩展原生规则解释、来源绑定和领域阅读折叠。
领域展示不能将尚未解释的推导变成已检查的证据。

策略顺序仍是行为的一部分：局部重构在产生第一份候选后停止；候选被检查器拒绝时，
必须保留可观察的缺口，不能用另一策略隐藏失败。多项式生成器已在返回前回放候选，
因此分发器不会在同一个共享截止时间下重复回放。这种工程组织不引入证明排名，
也不承诺最短证明；条件组的子集极小性保持原有含义。

局部假设不是全局事实
--------------------

区分三个信任问题
----------------

* **Z3 是否返回 UNSAT？** ``solver_status`` 回答这个问题，即使后续解释工作失败。
* **证明图是否对应输入且作用域闭合？** 输入和作用域检查将叶子绑定到精确输入出现位置，
  防止局部假设逃逸。
* **是否独立检查了每一步推理？** ``rule_check`` 和各节点的 ``local_check`` 单独回答。
  已识别的机械规则仍受信任于求解器；``reading_status="complete"`` 不代表完整独立证明内核的认证。

不支持的非线性、量词或其他理论规则会保留原生节点并标记缺口。可读标题不能删除缺口。
扩展解释器属于受信任的 Python 代码，其自身声明 ``checked``，不等于已经独立证明了该解释器的实现正确。
同样，加载快照会验证结构和引用，但不会认证来源。

最小化取决于条件分组
--------------------

假设两个源码语句产生了相同公式，原生叶子可能同时匹配这两个出现位置。
核保留其中一个，并不能说明这个具体来源具有唯一必要性。
将多个公式放在同一个标识符之下，就是有意将它们作为一个删除单位。

``subset_minimality="proven"`` 表示：针对最终集合及固定背景，已经逐个尝试删除每个保留的
可移除组，结果均为 SAT。UNKNOWN 不能支持删除或最小性声明。
可能存在不同的核和不同长度的证明。寻找数量最少的核、最短证明或对人最有用的解释，是另外的优化问题。

完整证明先于最小化生成。重新求证使用另一个执行 ID；节点 ID 不跨执行迁移。
可选工作超时会保留已完成的证据。期限是协作式的，不能像独立进程那样限制任意插件的运行时间或内存使用。

来源关系与未来的 BMC 接入
-------------------------

``logical`` 关联指向提交的条件出现位置；``construction`` 表示某个精确表达式的构造来源；
``context`` 提供周边应用信息。只有第一种关系表示逻辑输入出现位置，但它也不等于唯一必要来源。
一个包含两条赋值的完整 case，不能自动当作某条必要赋值的精确源码范围。

BMC 前端可以使用通用 API，而不让 solver 层依赖 BMC：

1. 在将初始条件、迁移关系、表达式有定义性和目标编码为公式时，分配稳定条件组 ID，并保留原始表达式。
2. 将语句和查询的源码范围保留在来源对象中，在构造时登记精确项绑定，不要解码生成变量的名称。
3. 通过 ``UnsatQuery`` 提交精确目标合取及显式固定背景；性质极性和时域含义留在 BMC。
4. 提供 ``SourceAdapter`` 及可选的 ``ReadingFolder``，描述 case 和 action；合并必须保持同样的证据边界。
5. 在 BMC 中将求解结果解释为有界性质判定，同时为人和 LLM 保留证明完整度、来源完整度及核最小性的限定信息。

以上说明消费方的边界；这些 solver API 尚未实现 BMC 适配器，也没有替换其现有解释接口。
当前可直接运行的调用见 :doc:`/how_to/unsat_proofs/index_zh`。
