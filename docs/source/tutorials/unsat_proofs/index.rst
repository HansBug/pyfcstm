Read your first UNSAT proof
===========================

This tutorial starts with a Python conjunction and ends with an automatically
assembled, readable contradiction. Use a pyfcstm build containing
``pyfcstm.solver.explain_unsat`` and its existing ``z3-solver`` dependency.
No Lean installation, proof executable or LLM service is needed.

The solver API accepts formulas from any application. This tutorial does not
run BMC or change the meaning of a property verdict.

1. Name the original conditions
-------------------------------

A balance starts nonnegative and increases by one. Ask whether its next value
can be negative. Include an unrelated condition to show that an explanation
can use fewer conditions than the submitted query.

.. code-block:: python

    import z3
    from pyfcstm.solver import (
        SymbolNames, UnsatConstraint, UnsatQuery, explain_unsat,
    )

    before, after, noise = z3.Ints("before after noise")
    query = UnsatQuery("linear", (
        UnsatConstraint("initial", (before >= 0,)),
        UnsatConstraint("update", (after == before + 1,)),
        UnsatConstraint("goal", (after < 0,)),
        UnsatConstraint("unrelated", (noise >= 0,)),
    ))

Each identifier names a removable group. Each group's expressions are
conjoined; a group containing several expressions remains one unit during
minimization. The goal is an ordinary input condition here, not a special
solver command.

2. Generate the proof
----------------------

Give the actual symbols readable names and request evidence:

.. code-block:: python

    names = SymbolNames()
    names.register(before, "balance@0")
    names.register(after, "balance@1")
    report = explain_unsat(query, names=names)
    print(report.reading.to_text())

The following is the complete output of the checked-in example, generated by
Z3 and assembled by pyfcstm. Native proof order can differ between Z3 versions.

   :end-before: END linear en

The final arithmetic step adds three inequalities. Because balances are
integers, ``balance@1 < 0`` becomes ``balance@1 + 1 <= 0``. The balance
terms cancel and leave ``2 <= 0``. That contradiction rules out the submitted
conjunction. The unrelated condition is retained in the input table but is
not needed by this native refutation.

3. Inspect what the result promises
-----------------------------------

.. code-block:: python

    assert report.solver_status == "unsat"
    assert report.proof_status == "captured"
    assert report.input_check == "passed"
    assert report.scope_check == "passed"
    assert report.reading_status == "complete"
    root = report.reading.get_block(report.reading.root_id)
    premises = report.reading.expand(root.block_id)

``complete`` describes the readable derivation. It does not mean that every
native inference was independently checked: the arithmetic certificates are
checked using exact rational arithmetic, while recognized mechanical Z3 rules
can remain ``trusted``. Inspect ``rule_check`` and each node's ``local_check``
when that distinction matters. A partial result carries explicit ``gaps``.

Reproduce and continue
----------------------

Download :download:`proof.demo.py`, or run it from a source checkout with that
checkout on ``PYTHONPATH``:

.. code-block:: console

    PYTHONPATH=. python docs/source/tutorials/unsat_proofs/proof.demo.py --case linear --language en

The script also offers ``--case branches`` and ``--case sources``. It prints
actual proofs and writes no files. ``--minimize`` requests a subset-minimal
condition core and a new proof; ``--fold`` demonstrates a checked domain title
with expandable evidence. These are example-script options, not additions to
the ``pyfcstm bmc`` CLI.

Use :doc:`/how_to/unsat_proofs/index` for these tasks,
:doc:`/explanations/unsat_proofs/index` for the trust and provenance boundaries,
and :doc:`/reference/unsat_proofs/index` for the complete API contract.
