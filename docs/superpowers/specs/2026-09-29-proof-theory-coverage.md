# Proof coverage for generated solver formulas

## Objective

Extend the native proof reader to cover formulas generated by pyfcstm's solver,
verify, BMC relation and FBMCQ property encoders. The user explicitly authorized
implementation in the current checkout, TDD, 100% changed production branch
coverage, a new runnable-example PR comment and delivery ready for merge.
This extends the standalone proof subsystem; replacing existing BMC explanation
contracts is still a separate integration task.

## Required behavior

- Preserve exact original inputs, background, occurrence/source bindings and
  branch assumptions. No proof reconstruction from pretty-printed text.
- Cover Boolean control/selection, equality, PB cardinality, integer/real linear
  arithmetic, division/modulo, casts/rounding, and supported nonlinear expressions
  arising from the actual encoders, including combinations and negative operands.
- Distinguish solver UNKNOWN/timeouts from missing proof interpretation. An
  unsupported inference remains a visible gap until a real deduction explains it.
- Do not turn arbitrary theory lemmas into trusted generic prose to claim complete.
  Existing known mechanical trusted rules remain explicitly distinguished from
  locally checked certificates.
- Local reconstruction may use only a node's premises, conclusion and active
  hypotheses; an already contradictory full query must not justify arbitrary
  intermediate claims. A second UNSAT answer alone is not a readable derivation.
- Offline snapshots retain all added evidence and remain readable without Z3.
  No new runtime dependency, product schema version or global backend registry.
- Preserve Python 3.7–3.14 and Windows/Linux/macOS compatibility.

## Acceptance

Real encoder-driven regression cases cover guard tautology/contradiction, guarded
updates, selector equivalence, priority, short-circuit definedness, AtMost, integer
quotients/remainders, mixed sorts/rounding and nonlinear arithmetic. Within the
supported proof-producing domain they require captured evidence, exact input
binding, passed scope analysis and complete readable derivations without gaps.
SAT, UNKNOWN and exhausted budgets retain honest outcomes. Guard explanations
must not confuse inconsistent contexts or undefined evaluations with invariance.
Long text outputs use full text_aligner assertions. Changed executable statements
and branches have 100% coverage without exclusions; full regression, docs,
packaging, review and exact-final-head applicable CI pass. New PR examples pair
each executable input with its actual complete output; no manually authored
result is presented as generated. Do not merge the PR.

## Upstream semantics

Interpret native rule meanings against Z3's pinned API/proof implementation:
https://github.com/Z3Prover/z3/blob/z3-4.15.4/src/api/z3_api.h
Theory families and proof paths must be surveyed rather than inferred from
surface DSL operators. Version-dependent paths belong in compatibility tests.

## Proof package boundary

Keep all proof-specific implementation under `pyfcstm.solver.proof`, including native capture. Export public evidence and extension interfaces through its `__init__.py`; consumers must import from this package. Shared budgets, symbols and UNSAT query/core utilities remain in the parent solver package. Preserve offline loading without Z3.
