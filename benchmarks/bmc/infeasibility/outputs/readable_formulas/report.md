# Readable formulas and shared UNSAT kernel: compatibility measurement

Baseline: `92a85f1ec4e0db20e05e341e088931a49c91ced5`. Candidate: the shared solver,
construction-time symbol mapping and native formula rendering accompanying this report.
The earlier [core-contract measurement](../unsat_contract/report.md) covers the
preceding implementation, not this iteration.

## Protocol and retained gates

Each process loads the model, compiles the query and runs the public solve API,
including ordinary SAT replay. Interpreter startup/imports are outside API timing;
process peak RSS includes them. Four case families use the same two-state,
one-variable model at bound 8 and modes `none`, `formal`, `proof`.

Seven process pairs alternate baseline/candidate launch order. Within each pair,
both versions use the same permutation of all twelve combinations, generated by
Python `random.Random(9100 + repetition).shuffle`, for repetition 0 through 6.
Each process warms all combinations once, then measures each once in that order.
No sample is dropped and GC remains enabled; all GC time remains inside timing.
`gc_ms` and `gc_generations` are diagnostic fields, never subtracted from `ms`.
The same lightweight solver-call and GC callbacks instrument both versions.

The numeric gates remain those frozen for the earlier measurement:

- Default median <= `max(baseline * 1.05, baseline + 2 ms)`.
- Enabled explanation median <= `max(baseline * 1.15, baseline + 5 ms)`.
- Peak RSS median <= `max(baseline * 1.10, baseline + 8 MiB)`.
- Solver-check counts, property verdicts and achieved explanation modes must agree.

This protocol change was made after a fixed-order anomaly, not before all
experimentation. It changes sample order, not acceptance thresholds. See the
retained diagnostic observations below. A small solver-import regression test
also ran during the paired measurement; this was not an isolated machine run.

Timing gate failures: **transition_conflict/none exceeds 49.840 ms by 0.091 ms**. No thresholds were relaxed and this is not an all-gates-pass result.

Solver status, property truth, achieved explanation mode and solver-check counts
agree in every case/mode. Default overhead is construction-time registration;
default solves do not extract or render explanations. Enabled modes additionally
render original formulas, so this compares a richer output against the former prose.
The large proof improvement is from replacing string-based variable enumeration
with one AST-identity traversal in binding checks. It is not a general BMC speedup.

## Diagnostic evidence and limits

[fixed_order_diagnostic.json](fixed_order_diagnostic.json) retains the complete
seven-pair measurement before compact tuple records were introduced. In that
version, the fixed-position transition/default case was around 45% slower.
[gc_diagnostic.json](gc_diagnostic.json) retains direct GC probes: roughly 21 ms of
a 69 ms candidate call was generation-2 collection, absent at the matching baseline
position. Compact immutable records moved that collection into the formal case;
they did not make cumulative GC free. Randomized paired order avoids repeatedly
assigning that phase cost to one fixed case. Individual observations still include it.

The rendering micro-experiment used the actual bound step relation. Caching native
format objects for shared AST nodes outside quantifier scopes reduced rendering
from approximately 22 ms to 11 ms with the same 1832-character output. Caching
only native constant printing did not help and was not adopted. Operator formatting
is still delegated to Z3, and full expressions are not silently truncated.

This is a small local compatibility experiment, not a workload survey. It does not
establish costs for hundreds of long generated variables, large bounds, arbitrary
SMT theories, other platforms or future proof inference. The one marginal default
gate miss remains a review item rather than a passing result rounded to 5%.

## Reproduction

Extract baseline package source with `git archive 92a85f1 pyfcstm` into a temporary
directory, not a worktree. Run [worker.py](worker.py) with the source directory and
seed as arguments, e.g. `python worker.py BASELINE_DIR 9100`. Repeat for the candidate
with the same seed. Use seeds 9100–9106, alternating which version runs first.
Run processes sequentially; the worker warms before measurement. Linux `resource`
reports RSS in KiB for this experiment. Raw paired observations are in
[samples.json](samples.json).
